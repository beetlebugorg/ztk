For agents

Build it, see it, check it, ship it.

An agent gets the same view of the app as a person. The tools are commands of ztk, so a check is a Tcl script that runs in CI.

Works

See

ztk::snapshot . gives a PNG of the window. ztk --headless --screenshot writes one with no display. It renders with the CPU renderer on each platform.

Works

Read and drive

ztk::tree lists each widget with its class and its box. ztk::inject sends a click, a key, or text through the hit test and the focus, as a real backend does.

Works

Trust

A script has the commands of Tk and of the ztcl core. Host access needs --allow. In a browser a script has no file, network, or process access. The code is short, so a person can read it.

Works

Ship

ztk bundle makes one program file for Linux, macOS, or Windows, or a signed macOS app, from any computer. An app in one file. A build from the web page is in progress.

Themed widgets

ttk widgets, modern or classic.

The same script in two themes. ttk::button, ttk::checkbutton with the switch style, ttk::radiobutton, ttk::entry, ttk::labelframe, ttk::separator, and ttk::sizegrip keep the options and the messages of wish. ttk::style restyles them, and each setting becomes a CSS rule.

Accent.TButton
ttk::style configure Accent.TButton \
    -foreground white \
    -background #2563eb
ttk::style map Accent.TButton \
    -background {active #1d4ed8}
ttk::button .ok -text "Apply" \
    -style Accent.TButton
/* the same rules in CSS */
TButton.Accent {
  color: white;
  background-color: #2563eb;
}
TButton.Accent:hover {
  background-color: #1d4ed8;
}

Themed widgets documents each ttk widget, and Styling and themes has ttk::style.

What it renders

Tk scripts, rendered by ztk.

When a card scrolls into view, its script runs live in its place: ztk in WebAssembly, rendered with WebGPU where the browser has it and WebGL 2 elsewhere. Click, type, drag, and toggle in it. Each script also runs in wish 8.6, and the cards follow the color scheme of your system.

Make the images again with zig build and tools/shots.sh. One image: ztk --headless --scale 2 --exit-after-frames 1 --screenshot out.png script.tcl, with --dark for the dark scheme.

Fluid

Smooth frames, even with a busy script.

The script makes a scene of quads, and a render thread renders it. The render thread also moves transitions, switches, sliders, and scrollbars by its own clock, so they keep moving while your script works.

No frames when idle

A window with no change renders no frame and wakes no thread.

Fast to start

1.6 ms from start to the first frame on the headless backend, and 3.0 ms on Wayland. The demo uses 11.2 MB of private memory.

Animation in the API

CSS transitions, @keyframes, springs, and ztk::animate for widget options and canvas items. Reduced motion shows each end state at once.

All the numbers

Native GPU rendering

One renderer for each platform API.

Each platform renders with its own GPU API, with no translation layer between ztk and the driver. ztk does not use MoltenVK, ANGLE, or DXVK. A CPU renderer gives the same image on each machine, and the tests compare the GPU output with it.

Works

CPU renderer

The reference renderer. It renders the demo into a Wayland shared memory buffer and into a framebuffer.

Works offscreen

Vulkan on Linux

The Vulkan renderer matches the CPU renderer on two GPUs, within 2 levels. The swapchain on a window is not written yet.

Works

AppKit and Metal on macOS

Native windows rendered with Metal, the system menu bar with NSMenu, input methods, the clipboard, file dialogs, the Dock, the tray, and dark mode and the accent color.

Works

Win32 and Direct3D 12 on Windows

Native windows with a Direct3D 12 swapchain, text with DirectWrite, native menus, input methods with TSF, the clipboard, file dialogs, the taskbar, the tray, and dark mode.

Works

WebGPU and WebGL 2 on the web

WebGPU with WGSL shaders where the browser gives an adapter, else WebGL 2, else the CPU renderer into a 2D canvas. No library is in the WebAssembly file.

Planned

X11 on Linux

With libxcb and Vulkan.

Modern features

Style Tk widgets with CSS.

A stylesheet in a subset of CSS gives the default look. Styling and themes has the details. Your stylesheet changes it, with selectors, states, variables, and transitions.

  • A modern theme from a stylesheet, with a dark scheme.
  • A font engine with no library. It reads TrueType outlines and the kerning of the GPOS table.
  • A classic theme with the sizes and the colors of Tk on X11.
  • Transitions and keyframes on each state, with springs.
style.css
Button {
  border-radius: 6px;
  padding: 6px 12px;
  transition: all 120ms;
}
Button:hover {
  background: var(--accent);
  color: var(--accent-fg);
}

Built on ztcl. No bloat.

The sandbox of ztcl, and no third-party library.

ztk adds the Tk commands to ztcl and uses it as a Zig package. It needs only the interfaces of the platform, ztcl, and the Zig standard library. The build has two dependencies: ztcl, and the Vulkan headers for the types of Vulkan. Through ztcl it also builds libghostty-vt for ztk::terminal. The font reader and rasterizer, the text shaping, the PNG code, the CSS engine, and the renderers are code of ztk. ztk.wasm on this site is 6,103,995 bytes, and 1,887,009 bytes with gzip -9 (measured 2026-11-26).

No capability by default

The ztk library turns on no capability of ztcl. It reaches the host only through its backend. Only the ztk program turns on a capability, from a flag.

One static program

The core, the text code, the headless backend, and the direct backend link no library. The build with the direct and headless backends and no Vulkan is one static program.

Vulkan at run time

No build links the Vulkan loader. The program opens it at run time, so it also starts on a machine with no Vulkan.

Backends

Works

Headless

For tests and for the oracle that compares ztk with wish. It runs on Linux, macOS, and Windows. Pull requests check Linux, and the full run checks macOS and Windows every 6 hours.

Works

Wayland

Our own client of the Wayland protocol and the XKB key map, with no libwayland, so a static Linux program opens a window. The CPU renderer into shared memory. tests/wayland-input.sh checks keys, a resize, the scale 1.5, and the clipboard on a private headless sway.

Not tried on a device

Direct

For a Linux device with no display server: the framebuffer and evdev. Tests use fake hosts. --direct needs the flag --direct-unsafe-test-device.

Status

Experimental. ztk is not yet a drop-in Tk. The widgets of Tk 8.6 are in (with text, ttk::treeview, ttk::notebook, and native menus), and AppKit and Win32 backends render native windows. Still to come: the native look of each platform (#154), Vulkan on a window, X11, and the dialogs that ztk draws. The code and the docs were written largely with AI coding agents, under human direction, so review the code before you depend on it. Differences from Tk lists the gaps, and the plan has the roadmap.

The interpreter under ztk

ztcl: fast, sandboxed Tcl in Zig

A Tcl 8.6 interpreter with a bytecode VM, exact step and memory limits, real threads, and an optional JIT up to 28 times as fast as tclsh.
